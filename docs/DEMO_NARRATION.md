# English demo narration and recording checklist

Target: 2 minutes 40 seconds. Record actual interactions; do not substitute a mock model response. Use a separate ignored demo database, local mode, and show the local-mode badge. The final public upload requires an actual video file; this script alone is not a video.

## Narration

**00:00–00:20 — Dashboard**
“Recognising a worked answer is different from producing one yourself. RecallLab makes that difference visible. It is a study companion for mathematics for economics, built around an attempt, a reviewed hint, a retry, and a separate independent check.”

**00:20–00:55 — Misconception and honest local mode**
“Consider this claim: a zero derivative proves a maximum. I’ll make an attempt first. Cloud assessment is currently off because AWS declined our model-access request, so this explanation is saved for self-review. RecallLab tells me that plainly. I can now open one reviewed hint and inspect the original source note. The cubic graph shows why a stationary point can be neither a maximum nor a minimum.”

**00:55–01:25 — Actual symbolic check**
“Now I’ll try a numerical question. For this total cost function, I enter an incorrect result first. The server checks the maths locally. After correcting my derivative, I get a verified result. Learner input passes through a restricted mathematical grammar; it never executes as Python.”

**01:25–02:00 — Independent check**
“The independent check uses five different questions. Hints and marks are withheld until all answers are recorded. At the end, I can review my work. The dashboard counts independent results separately from assisted practice, and the review queue brings back ideas that needed another look.”

**02:00–02:25 — MCP and persistence**
“These are real MCP calls through the official browser client and Streamable HTTP server. Four tools manage sessions, attempts, reviewed help and progress. SQLite preserves my work across reconnects, and duplicate requests reuse a saved attempt.”

**02:25–02:40 — Evidence and next step**
“The local workflows pass automated tests and browser checks. Bedrock assessment, live model accuracy and a student pilot are still pending. The next test is whether students can solve parallel questions independently a day later. This is a web simulation of an Alexa+ use case, not a native Alexa integration.”

## Shot and privacy checklist

1. Use only the localhost app window; close inbox/account panels from the recording area. Never capture AWS credentials or account information.
2. Show a real wrong answer, corrected answer, hint/source and MCP activity.
3. Record the full five-question check separately, then use an explicit time cut if needed. Never imply hidden feedback was available early.
4. Add English captions and keep duration below three minutes. No copyrighted music or third-party footage.
5. Review the exported file before uploading. Public YouTube/Vimeo URL, judge access and event eligibility must be verified at submission time.
